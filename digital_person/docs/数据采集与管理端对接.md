# 数据采集与管理端对接说明

> 给管理端（数据大屏）开发的对接文档。**结论先行：你不用碰数据采集，只管读下面的 `GET /analytics/*` JSON 接口画图。** 采集这一段（客户端埋点 + 服务端落库）已由 RAG 端全部实现。

---

## 一、数据怎么从游客流到管理端（两类数据源）

```
游客端(手机网页)                 RAG 服务端(:8000 / 经桥接 :9000)        管理端(数据大屏)
   │                                    │                                  │
   │ 问答/拍照/语音                      │ ① 自动落库 conversations 表        │
   │ (/chat /chat/image /asr) ─────────▶│   问/答/情绪/意图/景区/时间         │
   │                                    │                                  │
   │ 行为埋点                            │ ② 落库 events 表                   │
   │ (/analytics/event) ───────────────▶│   画像/功能/到访/满意度             │
   │                                    │                                  │
   │                                    │◀──── GET /analytics/* ────────────│ 读聚合 JSON
```

- **① 自动埋点**：对话内容、情绪、意图、景区、时间 → 游客每问一句服务端自动写 `conversations` 表，无需客户端参与。
- **② 主动上报**：服务端从对话里看不到的信号（同行类型/语言/兴趣、用了哪些功能、到访了哪些站、满意度）→ 客户端 `POST /analytics/event` 上报，落 `events` 表。

两张表都在 `conversations.db`（SQLite）。管理端只读聚合接口，不直接碰表。

- 经桥接（前端同源，推荐）：`http://<桥接>:6006/rag/analytics/...`（AutoDL 桥接端口 6006；本地开发为 9000）
- 公网常驻测试：`https://u891802-x4xd-7f8146e7.bjb2.seetacloud.com:8443/rag/analytics/...`（AutoDL 单网关；ECS 已弃用）

所有接口都带 `?scenic_id=lingshan&days=7`（景区 + 统计天数，默认 lingshan / 7 天）。

## 三、管理端要读的接口（含真实返回样例）

### 1) `GET /analytics/dashboard` — 概览 KPI
```json
{
  "scenic_id": "lingshan", "period_days": 7,
  "total_conversations": 128, "total_sessions": 36,
  "satisfaction_rate": 0.74, "context_hit_rate": 0.91,
  "emotion_distribution": {"happy": 60, "neutral": 40, "curious": 18, "apologetic": 10},
  "daily_stats": [{"date":"2026-06-08","conversations":40,"sessions":12}, ...]
}
```
→ 画：KPI 数字卡（会话/满意度/命中率）、情绪饼图、每日趋势折线。

### 2) `GET /analytics/hot-topics` — 热门问题词云
```json
{"scenic_id":"lingshan","hot_topics":[{"word":"大佛","count":22},{"word":"门票","count":15}, ...]}
```
→ 词云 / 横向柱状。

### 3) `GET /analytics/sentiment-trend` — 满意度按天趋势
```json
{"scenic_id":"lingshan","trend":[{"date":"2026-06-08","positive":30,"neutral":8,"negative":2,"satisfaction":0.75}, ...]}
```
→ 堆叠面积 / 满意度折线。

### 4) `GET /analytics/knowledge-gaps` — 知识盲区（答不上的问题）
```json
{"scenic_id":"lingshan","gaps":[{"question":"有没有充电宝租借","count":4,"last_at":"..."}, ...]}
```
→ 列表，指导知识库补充。

### 5) `GET /analytics/alerts` — 负面情绪预警
```json
{"scenic_id":"lingshan","alerts":[{"session_id":"...","question":"...","emotion":"apologetic","at":"..."}, ...]}
```
→ 红色预警条 / 实时滚动。

### 6) `GET /analytics/crowd` — 客流热度（真实行为数据）
```json
{"scenic_id":"lingshan","has_data":true,"season":"旅游旺季","quiet_hours":"清晨8点前或傍晚17点后",
 "attractions":[{"attraction":"灵山大佛","crowd_level":"较多","crowd_index":0.78}, ...]}
```
→ 各景点拥挤档位条 / 错峰提示。注：黄山/故宫不在真实数据中 → `has_data:false`。

### 7) `GET /analytics/profile` — 客群画像 🆕（来自 events）
真实返回：
```json
{
  "scenic_id": "lingshan", "period_days": 7,
  "total_visitors": 2,
  "group_type": {"family_kids": 1, "couple": 1},
  "lang": {"zh": 2},
  "interests": {"history": 1, "food": 1, "culture": 1}
}
```
→ 同行类型占比环图、语言占比、兴趣 Top 柱状。
- `group_type` 枚举：`adult` / `family_kids` / `senior` / `couple`
- `lang`：`zh` / `en` / `ja` / `ko`
- `interests`：`history` / `nature` / `photo` / `food` / `culture`

### 8) `GET /analytics/feature-usage` — 功能使用率 + 满意度 🆕（来自 events）
真实返回：
```json
{
  "scenic_id": "lingshan", "period_days": 7,
  "active_sessions": 2,
  "feature_open": {"tour": 1, "facility": 1},
  "rating_count": 1, "avg_rating": 5.0
}
```
→ 功能使用率横向柱状、满意度均分仪表。
- `feature_open` 枚举：`tour`(跟我游) / `gps`(定位) / `facility`(找设施) / `trace`(足迹) / `photo`(拍照) / `voice`(语音) / `postcard`(明信片)
- `avg_rating`：1–5 均分（无评分时为 `null`）

### 9) `POST /analytics/report` — 游客感受度报告（LLM 生成，按需点）
```jsonc
// 请求 body: {"scenic_id":"lingshan","days":7}
{"scenic_id":"lingshan","period_days":7,"report":"## 总体满意度…（Markdown 文本）"}
```
→ "一键生成报告" 按钮 → 渲染 Markdown。

## 五、客户端已埋的事件（管理端无需关心，仅备查）

游客端在这些时机自动 `POST /analytics/event`：

| 时机 | type | payload |
|---|---|---|
| 进入导览 | `session_start` | `{interests:[], device}` + group_type/lang |
| 打开功能 | `feature_open` | `{feature}` |
| 听某站讲解 | `station_visit` | `{name, via: tour\|gps}` |
| 拍照定位成功 | `photo_locate` | `{location}` |
| 走完路线/生成明信片 | `milestone` | `{kind: route\|postcard}` |
| 退出（sendBeacon） | `session_end` | `{duration_s, asks, photos, visited}` |
| （预留）评分 | `rating` | `{score: 1-5, comment?}` |

> `rating` 接口已就绪，前端待加一个"好不好用"的点赞/打分入口即可点亮满意度面板。

## 六、给管理端的一句话

把上面 8 个 `GET` 接口接进 ECharts 即可；返回都是普通 JSON、无鉴权、支持跨域。新增的 `/profile` 和 `/feature-usage` 是这次为画像/功能两块大屏补的，数据已经在真机点击中实时累积。
