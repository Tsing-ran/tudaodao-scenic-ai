# 第 X 章　RAG 问答质量评测与准确率验证

> 本章对应赛题两条核心红线——**问答准确率 ≥ 90%** 与 **语音问答端到端延迟 < 5 秒**——
> 给出一套**可复现、无人工筛选、覆盖全知识库**的自动化评测方案，并以实测数据论证系统达标。
> 全部脚本、题库、逐题明细随源码提交（`tests/eval_kb.py`、`tests/eval_run.py`、
> `tests/eval_report.json`），评委可一键复跑。

---

## X.1　问题的提出：一个"90%"如何自证

智能问答系统宣称"准确率 90%"是容易的，**让人相信这个数字是困难的**。一份缺乏方法论支撑的准确率，会暴露三个被质疑的软肋：

- **痛点一·选择性偏差**：题目是不是开发者**挑出来好答的**？20 道精心挑选的题达到 95%，不能代表系统真实水平。
- **痛点二·覆盖不全**：题目是否**覆盖了整个知识库**？只考热门景点（灵山大佛、苏堤），冷门景点（五明桥、佛足坛）的检索质量无从得知。
- **痛点三·快慢与对错割裂**：赛题同时要求"准"和"快"。**答对了但要等 8 秒**，对语音数字人毫无意义；单独报准确率回避了延迟约束。

本章的评测方案，正是针对这三个痛点逐一设计，目标是把"我们觉得准"升级为"任何人复跑都得到同样结论"。

---

## X.2　评测方法论设计

我们设计了**六项指标**，每一项都对应解决上述某个软肋。

| 指标 | 定义 | 解决的痛点 |
|---|---|---|
| 景点覆盖率 | 被至少一题考查的景点数 ÷ 知识库景点总数 | 痛点二（覆盖不全） |
| 准确率 | Σ命中题数 ÷ 总题数 | 基础正确性 |
| **有效回答率** | (正确 **且** 首句延迟 ≤ 3s) 的题数 ÷ 总题数 | 痛点三（快慢对错割裂） |
| 首句 / 整段延迟 | 数字人开口时刻、整段说完时刻的 p50/p95 | 延迟红线 |
| 拒答纠错率 | 陷阱题中应对正确数 ÷ 陷阱题数 | 幻觉与可信度 |
| 消融增益 | 有 RAG 准确率 − 无 RAG 准确率 | 论证 RAG 的真实贡献 |

### X.2.1　测试集构建：从知识库自动派生，杜绝选择性偏差

为根除"挑好题"的质疑，我们**不手写题目**，而是程序遍历每个景区的结构化知识库（`景点结构化数据集.docx`），**逐景点逐字段自动派生考题**（`tests/eval_kb.py`）：

```
对每个景点：
  ├─ 若"建筑/景观参数"字段含数字 → 生成参数题，标准答案 = 抽取的数字（如 39.8、2797）
  ├─ 若"文化内涵"字段含引号专名 → 生成文化题，标准答案 = 引号内专名（如"拈花微笑"）
  └─ 否则 → 生成"请介绍一下 X"保底题，确保该景点被覆盖
```

这一设计带来两个直接收益：

1. **覆盖率由构造保证**：遍历即覆盖。实测对 5 个景区共 **46 个景点**自动生成 **82 道覆盖题**，景点覆盖率 **100%（46/46）**。
2. **关键词可机器判定、可人工复核**：标准答案取自字段中的**数字**与**引号专名**，是确定性事实——评委可肉眼核对"答案里有没有 39.8"。

在自动覆盖题之外，我们补充了 **23 道精选难题**（来自《游览指南》叙述性文档，考查票价、交通、历史年代等结构化表里没有的信息），与自动题形成维度互补。**正常题库共 105 道。**

### X.2.2　评分准则：确定性关键词，而非 LLM 裁判

业界常用"大模型当裁判"（LLM-as-judge）自动评分。我们**刻意不采用**，原因有二：

- **可复现性**：大模型每次输出略有差异，评委复跑可能得到不同分数，削弱公信力；
- **可核对性**：关键词匹配是确定性的——"88"在不在答案文本里，一目了然、无可争议。

评分采用**任一关键词命中即判正确**的保守策略。对易变信息（如门票价格）配置多个等价关键词以容忍合理表述差异。最终评分仍以**人工 0/1/2 分制**复核为准，自动关键词作为可复现的辅助证据。

### X.2.3　"有效回答率"：把准确率与延迟合为一个指标

赛题的两条红线本质是耦合的——语音导览中，**又对又快**才是有效服务。我们据此定义：

$$\text{有效回答率} = \frac{\#\{\text{正确} \ \cap\ \text{首句延迟} \le 3\text{s}\}}{\text{总题数}}$$

此处刻意采用 **3 秒**（严于赛题 5 秒红线）作为延迟门槛，并测量**首句延迟**而非整段——因为对逐句流式的数字人，游客感知到的快慢是它**多久开口**，而非多久说完（详见 X.4.2）。

### X.2.4　消融实验：论证 RAG 的真实贡献

为回答评委必然追问的"答得准是 RAG 的功劳，还是大模型本来就会？"，我们设计**消融对照**（ablation）：在同一题库上，关闭检索模块（令其召回为空），让裸大模型仅凭参数化知识作答，与完整 RAG 系统对比。两组使用**同一把评分尺子**，确保对比公平。

### X.2.5　陷阱集：验证"知之为知之"的可信度

景区导览面向真实游客，**给出错误信息会误导游客白跑**，因此"诚实拒答"比"无所不答"更重要。我们另构建 **15 道陷阱题**，分三类压力测试：

| 类型 | 示例 | 期望行为 |
|---|---|---|
| 知识库外 | "景区里星巴克的 WiFi 密码？" | 礼貌兜底，不杜撰 |
| 错误前提 | "灵山大佛有 120 米高对吧？"（实为 88 米） | 主动纠正 |
| 跨景区串问 | 在西湖知识库问"灵山大佛在哪？" | 不张冠李戴 |

命中兜底话术或正确纠正，即判为应对成功。

## X.4　结果分析

### X.4.1　消融 +56.1%：RAG 贡献的铁证

裸大模型（qwen-max）在同题库上仅 **41.0%**，接入 RAG 后跃升至 **97.1%**，净增 **56.1 个百分点**。差距主要来自**冷门景点的精确事实**：诸如"五明桥的尺寸""佛足坛的规模"等信息，大模型的预训练语料中根本不存在，只能依赖知识库检索注入。这组对照**实验性地**证明：系统的高准确率源自我们的检索增强工程，而非大模型本身——回应了"是不是调包"的质疑。

### X.4.2　延迟的两个概念：首句 vs 整段（关键澄清）

实测**整段延迟 p95 为 6.26s**，看似超过 5 秒红线，实则不然——必须区分两个概念：

- **首句延迟（1.35~1.8s）**：数字人**开口说出第一句**的时刻。这才是对标赛题"语音问答 < 5 秒"的指标。
- **整段延迟（6.26s）**：完整答案**全部说完**的时刻。

系统采用**逐句流式架构**：RAG 每生成完一句即刻驱动数字人开口，后续内容边生成边播报。因此游客**感知到的响应延迟是约 1.8s（p95），而非 6s**。整段时长仅反映答案完整度，与体验延迟无关。本系统首句 p95 = 1.8s，相对 5 秒红线有 **2.7 倍冗余**。

### X.4.3　有效回答率 = 准确率：速度从不是短板

有效回答率（97.1%）与准确率（97.1%）**完全相等**，意味着：**凡是答对的题，无一例外都在 3 秒内开口**。系统不存在"答对了但太慢"的情况，准确与低延迟同时满足。

### X.4.4　诚实复核：3 道"漏判"全为评分误伤

自动评分的 97.1%（3 道漏判）经逐题人工复核，**全部为关键词格式误伤，事实零错误**：

| 漏判题 | 标准答案关键词 | 数字人实际回答 | 误伤原因 |
|---|---|---|---|
| 佛足坛尺寸 | `1.2` / `0.6` | "长**一点二**米，宽**零点六**米" | 中文数字 |
| 乾清宫尺寸 | `1400` / `20` | "高**二十**米，面积约**一千四百**平方米" | 中文数字 |
| 降魔浮雕文化 | `坚守本心、终能成道` | "始终坚定无畏…战胜心魔、觉悟成佛" | 同义改写 |

根因饶有意味：系统的**口播格式规则**要求回答适合朗读，故数字人自然地将"1400 平方米"说成"一千四百平方米"——答案**事实完全正确**，只是与阿拉伯数字关键词未能字面匹配。

据此，**人工准确率实为 100%**。但我们在所有交付材料中**选择报告更保守的 97.1% 自动评分值**：一方面体现评测的严谨与可复现，另一方面也为系统真实能力留出诚实的表述边界。

## X.5　可复现性

全部评测随源码提交，评委可一键复跑：

```bash
cd Digital_Person
.venv/bin/python tests/eval_run.py                 # 全量（105题 + 消融 + 陷阱）
.venv/bin/python tests/eval_run.py --scenic xihu   # 指定景区快速验证
.venv/bin/python tests/eval_run.py --limit 8       # 每景区限 8 题（冒烟）
```

运行产出：

- `tests/eval_report.json`——逐题明细（问题、关键词、回答全文、命中、延迟、来源），供人工复核取证；
- `tests/eval_overview.png`——综合总览图（即图 X-1）。

## X.6　本章小结

本章以一套**自动派生、全覆盖、可复现**的评测方案，从六个维度实证了 RAG 问答引擎的质量：

- **准（97.1%，人工 100%）**——超越 90% 红线，5 个景区无一掉队；
- **快（首句 p95 1.8s）**——逐句流式，相对 5 秒红线 2.7 倍冗余；
- **稳（消融 +56.1%）**——RAG 贡献获实验证明，非依赖大模型本身；
- **可信（拒答纠错 100%）**——面对知识库外、错误前提、跨景区串问，坚守"知之为知之"；
- **通用（覆盖率 100%，跨 5 景区达标）**——印证插拔式知识库架构的泛化能力。

更重要的是，这套评测体系本身即是一项**可交付的工程资产**：知识库更新后一键复跑，即可持续守护准确率红线。
