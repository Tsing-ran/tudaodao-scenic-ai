# 数字人自然度 诊断 + 选型报告

> 背景：当前数字人（LiveTalking + MuseTalk V1.5）说话时嘴型/表情怪、有恐怖谷。
> 本报告定位根因、横评 GitHub 现成方案、给出兼顾「直播态实时」与「演示视频惊艳」的分层策略。
> 关联：[[OpenAvatarChat吸收方案]]、CLAUDE.md「数字人选型决策」。

---

## 1. 根因诊断：恐怖谷从哪来

MuseTalk 的工作方式：**只重生成嘴部一小块、贴回原帧；脸的其余部分（眼神、眉、面部肌肉、头动）逐帧原样复制 idle 底座视频**。
代码确认：`~/Desktop/LiveTalking/avatars/musetalk/genavatar.py:136-137` 把底座帧原样写入 `full_imgs/`，运行时只换嘴部 crop。

两个独立的违和来源：

1. **静态脸（主因）**：说话时只有嘴动，眼神/表情是死的 → 「活人嘴 + 蜡像脸」。底座越写实越放大违和。
2. **嘴部接缝/下巴（次因）**：嘴部 crop 贴回时的边界、牙齿、下巴融合不自然。

**关键利好**：两者各有便宜的调节杆，且都不牺牲实时性：
- 静态脸 → 换一个有自然眨眼/微动的 idle 底座（当前 wanx 图生视频的 idle.mp4 很可能有 AI 漂移/形变伪影，本身就怪）。
- 嘴部接缝 → MuseTalk 烘录参数 `bbox_shift` / `extra_margin` / `parsing_mode` / `cheek_width`（`genavatar.py:49,112,122,140`），重烘一次 ~2 分钟即可调。

## 2. 贯穿全局的取舍：实时 vs 自然

| | 实时（<5s 直播） | 离线（预渲染） |
|---|---|---|
| 能做什么 | 现场问答即时开口 | 固定台词高质量出片 |
| 自然度天花板 | 中（贴嘴类）/ 中高（Ditto） | 高（全脸表情扩散模型） |
| 代表 | MuseTalk、Ditto | Sonic、EchoMimic、Hallo、InteractAvatar |

赛题红线是「语音问答 <5s」，所以**最自然的扩散类做不了现场直播**（每秒视频要算几秒到几十秒）。这条物理约束决定下面的策略。

## 3. 候选横评（已查实）

| 项目 | 实时? | 显存 | 表情/情绪 | 许可证 | ComfyUI | 集成成本 | 定位 |
|---|---|---|---|---|---|---|---|
| **MuseTalk**（现用） | ✅ 30fps | ~7G(batch4) | ❌ 仅嘴 | 开源友好 | 有 | 0 | 直播主力，调参榨潜力 |
| **Ditto**（antgroup, MM2025） | ✅ 号称实时 | A100+TensorRT 实测；4080 存疑 | ✅ 情绪/视线/姿态可控 | 开源 | 有(三方) | 高（换整条直播引擎） | 实时表情，高风险候选 |
| **LivePortrait**（快手） | 近实时 | 中 | ✅ 眨眼/微表情(retarget) | 开源 | 有 | 低（仅离线生成底座） | 给 MuseTalk 造更活的 idle 底座 |
| **EchoMimic V1/2/3**（蚂蚁, AAAI25） | ❌ 离线(~5×实时) | 16G+ | 中(landmark) | Apache-2.0（最干净） | 有 | 中 | 演示视频预渲染（首选） |
| **Sonic**（腾讯/浙大, CVPR25） | ❌ 离线 | 32G 实测 | ✅ 自然全脸+头动 | ⚠️ 非商用 | 有 | 中 | 演示视频预渲染（注意许可证） |
| **InteractAvatar**（arXiv 2602.01538） | ❌ 离线(40步去噪) | 未公布 | ❌ 物体互动方向 | Apache-2.0 | 无 | 很高（研究代码） | 人-物互动，赛期不碰 |

## 4. 两个关键问题的直接回答

**ComfyUI 能借鉴吗？** 能，但它是**离线生成工具、不是直播引擎**：
- ✅ 用法 A：接 EchoMimic/Sonic **预渲染演示视频「英雄镜头」**（全脸表情、自然神态）。
- ✅ 用法 B：接 LivePortrait **离线生成更自然的 idle 底座**喂给 MuseTalk。
- ❌ 当不了现场 <5s 的实时引擎。

**清华那套「表情管理」能搬吗？** 其惊艳 demo + ComfyUI，几乎可以肯定是**离线扩散渲染**（Sonic/EchoMimic/Hallo 类），不是现场直播。观感可借——**用在演示视频里**；别指望替换直播引擎。

**用户发的 InteractAvatar 定位校正**：它做的是「数字人与实物互动讲解」（拿/指/触碰），**不是表情管理、也不实时**（40 步去噪离线出片），解决不了直播恐怖谷。赛期不建议碰。另注意 **StreamAvatar（arXiv 2512.22065，实时流式扩散）** 是「实时+扩散」的潜在新方向，记为观察项，赛期不押注。

## 5. 推荐策略（直播态 + 演示视频，分两条线）

### 线 A — 直播态止血（低风险，先做，保住 <5s）
1. 换更自然的 idle 底座：用 **LivePortrait** 从古风肖像生成带自然眨眼/微头动的循环底座，替换 wanx 的 idle.mp4 → 直击「静态脸」主因。
2. 调 MuseTalk 烘录参数：网格试 `bbox_shift`（±5~10）、`extra_margin`、`parsing_mode=jaw/raw`、`cheek_width` → 改善嘴部/下巴接缝。每组重烘 ~2 分钟、肉眼择优。
> 二者都不动现有 RTMP+桥接架构，仍实时。

### 线 B — 演示视频惊艳（中风险，赛前做）
3. **ComfyUI + EchoMimic（Apache-2.0）预渲染 2-3 个英雄镜头**（开场自我介绍、固定金句），剪进 7 分钟演示视频。
> Sonic 观感更好但非商用许可，优先 EchoMimic。

### 线 C — 拉伸项（高风险，有余力再碰）
4. 评估 **Ditto** 在 4080 上的实时可行性：clone 跑官方 demo，测 RTF/首帧延迟/是否必须 TensorRT。RTF<1 且显存<11.6G 才进入「替换 MuseTalk」评估；否则放弃，不影响 A/B。

## 6. 落地清单（按需逐步执行）

| 步骤 | 动作 | 验证标准 |
|---|---|---|
| S2 | clone LivePortrait，从古风肖像生成自然 idle 底座 → 重烘 avatar | 肉眼：脸不再「死」，对比现状 |
| S3 | MuseTalk 调参网格（bbox_shift/extra_margin/parsing/cheek） | 选出最自然一组，固化进烘录命令 |
| S4 | clone EchoMimic(+ComfyUI)，预渲染 1 个英雄镜头试片 | 输出全脸表情自然的样片 |
| S5（拉伸） | clone Ditto，4080 跑官方 demo 测实时性 | RTF<1 且显存<11.6G 才进「替换」评估 |

> clone 目标放 `~/Desktop/`（与 LiveTalking 同级，不污染本项目仓库）。

## 7. 验证方法

- **主观 A/B**：同句、同形象，改前 vs 改后并排录屏，2-3 人盲评「哪个更像真人」。
- **客观**：直播态须保持 `curl :1985/api/v1/streams/` active、首句端到端 <5s。
- **演示视频**：英雄镜头单独成片，与直播态片段剪辑衔接，不要求实时。
